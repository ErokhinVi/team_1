# Контракт блока cib

Сюда вписывай ручки, которые твой блок отдаёт наружу. Соседи по команде
видят только этот файл — не код. Если ручка изменилась или появилась новая —
обнови этот файл, иначе сосед о ней не узнает.

## Что я отдаю наружу

### GET /health
Проверка живости. Возвращает `{status, team, block, commit, backend_url, products}`.

### GET /products
Каталог продуктов команды. Возвращает `{total, items: [продукты]}`. Каждый
продукт — объект как минимум с `{id, kind, name}`; депозитные/кредитные могут
иметь `rate_pct`.

### GET /
HTML с каталогом продуктов. Для человека, не для других блоков.

## Кого я зову у соседей

- backend: пока никого; появится, когда логика решения попросит данные клиента
- retail: я никого не зову у retail — это retail зовёт меня

`http://localhost:8002` (порт фиксируется docker-compose).

## Контекст для коллег — 9 октября 2026

Задача команды — кредитная функция. Подготовка CIB завершена, но кредитный
продукт и решение ещё **не реализованы**. Развёрнутый контекст хранится в
`cib/CONTEXT.md`; эта сводка продублирована здесь для участников, которым
доступен только контракт.

План CIB: условия продукта, расчёт платежа, решение с понятной причиной
и посильное встречное предложение. Предполагаемый путь решения:
`POST /credit/decide`; **ещё не доступен**, формат нужно согласовать.

От блока данных нужны данные клиента и кредитная история. Для полного
оформления также нужны сохранение заявки/результата и согласованный учёт
выдачи без повторного зачисления. От приложения — форма суммы/срока,
показ условий и всех исходов решения, согласие клиента и статус заявки.
Конкретные новые обращения к соседям пока не согласованы.

Для интеграции важно: отсутствие истории не равно плохой истории;
прошлая просрочка не равна текущей. Текущий платёж и остаток долга не
представлены отдельными полями в исходных кредитных записях.

После отправки работы обновляется только изменённый блок; изменение
документа в `cib/` тоже запускает его обновление. Судейство ожидается
после появления новой работающей версии, а не в момент отправки.
Точные критерии и интервал опроса неизвестны. Нельзя считать создание
кредитной функции завершённым до проверки соединения всех трёх блоков.
